# 実行時APIとゲーム判定の境界（v2）

OpenAIとAnthropicを同じ行動提案インターフェースで扱う。開発時のモデル割当や未確認の価格表は、実行時の仕様に含めない。

| 処理 | 担当 | 呼び出し |
| --- | --- | --- |
| 地形生成・戦闘・移動・視界・アイテム・野営 | ローカルのゲームエンジン | なし |
| 定型の内蔵アクション | `localProposal` → `Game.prepare` | なし |
| 自由文章の解釈 | 選択した提供元・モデル → `Game.prepare` | 提案ごとに1回 |
| 成功率・対象・消費・効果量の決定 | `Game.prepare` | なし |
| d6判定・効果適用・敵の行動 | `Game.execute` | なし |
| 提案失敗・中止・取り消し | エラー表示のみ | 自動再試行なし |

既定モデルはOpenAI `gpt-6-luna` / Anthropic `claude-haiku-5-5`。モデルIDはユーザーが変更できる。利用権限と構造化出力の対応は各提供元に依存する。

OpenAIではResponsesの`text.format`にStrict JSON Schemaを指定し、`store: false`とする。AnthropicではMessagesの`output_config.format`にJSON Schemaを指定する。APIキーを別々に保持し、モデルとキーを違う提供元へ送らない。固定HTTPSエンドポイントのみを使う。

## GMの出力契約

`js/llm.js`の`ACTION_SCHEMA`と`GM_PROMPT`が契約の正本。

- タイトル、方法と因果、能力、難易度、集中投入、成功／失敗時の描写。
- 1〜2個の具体的な効果と対象。近くの地形座標や敵の実在idを使用。
- 使い切る材料は所持品idで最大2個。
- HP、経験値、レベル、勝利、ターン数を直接設定するフィールドを持たない。
- 巨大な願いは局所的な一歩へ縮め、描写と実効果を合わせる。

送信する情報はプレイヤー、現在見える敵、4マス以内の地形、選択対象、近くの創作物、直近12件の成功記憶、攻撃予告。提供元に関係なく同じコンテキストを使う。プレイヤーの入力は資料として扱い、システム指示とは分離する。

## エンジンの検証

`Game.prepare`は世界を変えず、効果種、対象の実在・視界・距離、座標、保護地形、重複、材料を検証する。効果ごとの最低コスト・難易度を適用し、集中投入を1〜5に制限する。守護者は追加制約を持つ。数値の効果量、道具加点、環境加点、属性相性はエンジンが計算する。

`Game.execute`は提案のリビジョンを照合し、集中と材料を消費してから、セーブされる乱数状態でd6を判定する。成功時のみ世界を変更して記憶へ残す。成功／失敗のどちらも1ターン進む。移動・通常操作が入った後に古い提案を実行できない。

## 検証

`npm test`で両APIのURL・認証ヘッダー・リクエスト形式・構造化出力の解析、不完全応答、拒否、JSONエラー、401/403/429/500、タイムアウトとキャンセルをモック検証する。ゲーム側は到達性、攻撃予告、資源・空腹、死亡、自由行動、属性相性、記憶、保存と復元、個別名・固定補正、識別、合成、投擲、扉、探索、長押しの経路と停止を検証する。

`tests/browser_smoke.py`はブラウザで両APIの送受信をモックし、UIから提案・実行する経路と、提供元ごとのキーの保存・消去を確認する。実際のAPIキーを使う疎通・モデルの判定品質・Safari実機は別途確認が必要。

## 個別アイテムと秘匿情報

`publicItem`で所持品・装備・選択アイテムを公開表現に変換する。未識別の補正と装備の量は送信しない。床に置いた品の情報からも内部実体を除く。識別成功後だけ事前の量を提示する。名前と物語、基本の効果、材料としての性質は渡す。

「名前を活かす」から提案する場合、選択した消耗品のidを`Game.prepare`が消費リストに強制追加する。GMが`consumes`を空にした場合も品を失う。提案の取り消しは無料で、実行の成功・失敗時だけ消費する。

配置・合成の名前生成、補正、識別、合成の判定と通常使用はすべてローカル処理。APIを使って名前を量産しない。新しい既定モデルの送信と構造化出力の解析はモックで検証する。提供元での実際の利用権限・モデルの提供状況は別途実キーで確認する。
